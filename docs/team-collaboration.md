# 云雀笔记 · 团队协作指南

## 协作模型

团队版以"共享知识库"为协作单元。一个共享知识库是一份被多个成员同时挂载的
知识库目录，其同步由一个团队同步服务（SaaS 或私有化部署）协调。

成员对共享知识库的权限分为四档：

| 权限 | 阅读 | 评论 | 编辑 | 管理成员 | 删除知识库 |
| --- | --- | --- | --- | --- | --- |
| 只读 | 是 | 否 | 否 | 否 | 否 |
| 可评论 | 是 | 是 | 否 | 否 | 否 |
| 可编辑 | 是 | 是 | 是 | 否 | 否 |
| 可管理 | 是 | 是 | 是 | 是 | 是 |

权限按成员粒度授予，也支持先建立"成员组"再整组授权。成员的最终权限取
所有授权来源中的最高值。

## 建立共享知识库

1. 由"可管理"权限的成员在"团队 → 共享知识库 → 新建"中创建。
2. 选择初始内容：空白、从现有个人知识库复制，或从模板创建。
3. 邀请成员。邀请通过邮箱或团队邀请链接发出，链接默认 7 天有效，
   可在生成时调整为 1~30 天。
4. 被邀请成员接受后，共享知识库会作为独立目录挂载到其本地。

从现有个人知识库复制时，只复制笔记正文与附件，不复制版本历史与
本地路径配置。

## 编辑与冲突

共享知识库的编辑采用**乐观并发控制**。每次保存时客户端会提交该笔记的
版本号，服务端校验版本号是否最新：

- 版本号一致 → 保存成功，版本号递增。
- 版本号落后 → 返回冲突，客户端弹出合并界面，展示"共同祖先 / 本地 /
  远端"三方对比。

三方合并的粒度是行。同一行被双方修改时标记为冲突，需人工选择保留哪一方。
合并结果会作为新版本提交，版本历史中会标注"合并自 v12 与 v14"。

## 评论与批注

选中任意文本后点击"评论"即可发起讨论。评论支持 @ 提及成员，被提及者会
收到通知（应用内 + 邮件，可在设置中关闭邮件）。

评论有三种状态：待处理、已解决、已归档。已解决的评论默认折叠，可在
侧边栏中切换显示。评论不占用版本号，但会记录在审计日志中。

## 变更审计

团队版记录每一次编辑的以下信息：

- 操作者、操作时间、设备标识
- 变更前后的笔记版本号
- 变更类型（新建、编辑、重命名、移动、删除）
- 差异摘要（新增/删除行数）

审计日志保留时长与套餐一致，团队版永久保留。可按成员、时间范围、
变更类型筛选，支持导出为 CSV。

**注意**：审计日志记录的是操作元数据与差异摘要，不存储笔记全文快照。
需要内容级回溯请使用版本历史。

## 成员离职处理

成员离职后应执行以下步骤：

1. 在"团队 → 成员"中将其状态改为"已停用"。停用后立即失去所有访问权限，
   但保留其历史操作记录。
2. 处理其未完成的待办与未解决的评论。可将评论批量转派给其他成员。
3. 回收席位。席位回收后，已支付的剩余费用按天折算退还到账户余额。

停用不会删除该成员创建的笔记。若需转移所有权，可在笔记属性中修改
"创建者"字段（需"可管理"权限）。

## 私有化部署

团队版支持将同步服务部署在企业内网。部署要求：

- 一台 Linux 服务器（4 核 8 GB 起），Docker 20.10 及以上。
- 对象存储（兼容 S3 协议）或本地磁盘，容量按"笔记总量 × 3"估算
  （含版本历史与审计日志）。
- 数据库：PostgreSQL 14 及以上。
- 若需对接企业身份提供方，需支持 SAML 2.0 或 OIDC。

私有化部署的数据不出企业内网。客户端与同步服务之间的通信使用 TLS 1.3，
服务端存储使用 AES-256 静态加密，密钥由企业自行管理。
