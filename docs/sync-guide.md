# 云雀笔记 · 同步配置指南

## 同步机制概述

云雀笔记采用**变更集（changeset）同步**模型。每次编辑会生成一条包含操作类型、
时间戳与设备 ID 的变更记录，同步时只传输增量变更，而不是整个文件。这使得
一次典型编辑的同步流量在 1~3 KB 之间，与笔记长度基本无关。

同步的前提是知识库目录被某个"同步载体"管理。软件本身不提供云端存储，
只负责检测变更、生成变更集、以及在冲突时给出合并建议。

## 方案一：Git 仓库同步

适合有版本管理习惯的用户，也是官方推荐的方案。

1. 在知识库目录执行 `git init`，添加远端并完成首次推送。
2. 打开"设置 → 同步 → Git"，勾选"启用自动提交"。
3. 设置提交间隔，默认 5 分钟，可调整为 1~60 分钟。

自动提交只包含笔记正文与元数据，`.lark/cache` 与 `.lark/tmp` 已被默认
加入 `.gitignore`。拉取时若检测到远端有新提交，软件会先执行 `git stash`，
拉取完成后再尝试自动合并；合并失败的笔记会生成 `.conflict` 副本并高亮提示。

## 方案二：网盘目录同步

把知识库放在坚果云、OneDrive、iCloud Drive 等同步盘的本地目录中即可。

需要注意三点：

- **避免多设备同时编辑同一篇笔记**。网盘只做文件级同步，无法理解内容冲突，
  后写入的一方会覆盖前者。建议在"设置 → 同步 → 锁"中开启文件锁提示。
- **排除 `.lark` 目录**。索引缓存体积可达正文的 30%，且频繁变动会显著增加
  同步流量。在网盘客户端中将 `.lark` 加入忽略列表。
- **首次同步前先暂停编辑**，等全量上传完成后再开始，避免产生大量冲突副本。

## 方案三：局域网直连同步

适用于同一办公网络下的多台设备，不经过任何第三方服务器。

在"设置 → 同步 → 局域网"中开启后，软件会通过 mDNS 广播自身信息，同一网段
内的设备可自动发现。点击"配对"后双方交换公钥，之后的通信使用 TLS 1.3 加密。

局域网同步的冲突处理策略与 Git 方案一致：按行级三方合并，无法自动合并时
保留双方版本。设备离线期间的变更会在下次上线时补齐。

## 冲突处理策略

软件提供三种冲突解决策略，可在"设置 → 同步 → 冲突"中选择：

| 策略 | 行为 | 适用场景 |
| --- | --- | --- |
| 保留双方 | 生成冲突副本，人工合并 | 单人多设备（默认） |
| 以最新为准 | 按时间戳取较晚的版本 | 单人设备间延迟较大时 |
| 以本机为准 | 本机版本始终优先 | 明确知道本机为权威副本 |

冲突副本的命名格式为 `笔记名 (冲突副本 设备名 20260925-1430).md`，合并完成后
可批量清理。

## 常见同步问题

**同步一直卡在"正在比对"**：通常是知识库文件数过多（超过 5 万个）。建议
按笔记本拆分为多个知识库，或改用 Git 方案。

**远端出现大量 `.conflict` 文件**：说明多台设备在离线状态下编辑了相同笔记。
建议统一冲突策略为"保留双方"，并约定同一时间只在一台设备上编辑。

**Git 方案提示 `detached HEAD`**：软件不会自动切换分支。请手动执行
`git checkout main` 后在设置中重新启用自动提交。
